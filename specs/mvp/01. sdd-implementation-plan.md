## SDD Workflow

For each implementation task:

1. Read the architecture and task document.
2. Tighten the task document if implementation details are missing.
3. Define API contracts, data contracts, and state transitions before coding.
4. Implement the smallest complete vertical slice for the task.
5. Add targeted tests for domain logic, API behavior, and failure paths.
6. Update the architecture or task document if implementation discovers a real constraint.
7. Mark the task complete only when its completion validation is satisfied.

## Global Completion Validation

The MVP is complete when [T-000 Global Acceptance](./tasks/t-000-global.md) passes.

At minimum:

- a user can connect Twitch
- followed channels sync and render correctly
- per-channel and global category preferences work
- monitored broadcasters have EventSub webhook subscriptions
- EventSub events update current channel state
- relevant state changes are stored
- matching events create deduplicated notification deliveries
- active PWA push subscriptions receive Web Push notifications
- operational jobs can reconcile EventSub subscriptions and refresh Twitch tokens

## Test Strategy

### Unit Tests

Cover:

- Twitch signature verification.
- token refresh decision logic.
- followed-channel sorting.
- preference matching.
- channel state transitions.
- notification deduplication keys.

### Integration Tests

Cover:

- OAuth callback with mocked Twitch responses.
- follow sync with paginated mocked Twitch responses.
- category preference creation and monitor setup.
- EventSub webhook challenge and signature verification.
- queue message processing into state changes.
- notification delivery creation from state transitions.

### Manual Checks

Cover:

- iOS installed PWA notification permission.
- push notification display.
- notification click behavior.
- mobile channel list layout and live duration display.
- per-channel and global preference creation/removal flow.
